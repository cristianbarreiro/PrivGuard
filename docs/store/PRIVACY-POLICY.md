## 1. Introduction

PrivGuard is a desktop application designed to manage and verify camera and microphone privacy controls on Windows computers. Depending on the selected protection layer and device capabilities, PrivGvard interacts with native Windows privacy preferences, Core Audio capture endpoint mute states, and Configuration Manager (PnP) device nodes.

PrivGuard is built with a strict **Local-First, Zero-Telemetry Privacy Architecture**. This Privacy Policy details what information is accessed, what is stored locally, how that data is safeguarded, and how you retain full control over your information.

---

## 2. Information Accessed & Processed

1. **Hardware & Device Identifiers:**
   - PrivGuard discovers connected camera and microphone devices using Windows Plug and Play APIs (`CfgMgr32.dll` and `Win32_PnPEntity`).
   - Device Instance IDs (e.g., `USB\VID_...`), friendly names, and audio endpoint GUIDs are accessed strictly to identify which device the user wishes to protect and to enable accurate restoration when unprotecting.
2. **System State & Privacy Preferences:**
   - Reads Windows privacy policy values under `HKCU` and `HKLM` (such as `LetAppsAccessCamera` and `LetAppsAccessMicrophone`).
   - Queries Core Audio endpoint mute status via Windows Core Audio COM interfaces.
3. **No Audio or Video Capture:**
   - **PrivGuard never accesses, previews, records, processes, or transmits camera video streams, images, microphone audio, or voice data.** The application only toggles hardware device availability and operating-system privacy flags.

---

## 3. Information Stored Locally & Storage Locations

All data generated by PrivGuard is persisted strictly on your local device beneath the Windows `%LOCALAPPDATA%` directory:

1. **User Preferences (`%LOCALAPPDATA%\PrivGuard\state.json`):**
   - Stores user interface language preferences, desired protection modes (Standard / Secure), autostart preference, and theme settings.
2. **Durable Privacy Session Journal (`%LOCALAPPDATA%\PrivGuard\Recovery\privacy-session-v1.json`):**
   - A Write-Ahead Log (WAL) that records the original state of hardware and policies before any mutation occurs.
   - Used exclusively to verify that previous system states can be restored cleanly during application shutdown or recovery after a crash.
3. **Active Session Marker (`%USERPROFILE%\AppData\Local\PrivGvard\Recovery\active-session-v1.marker`):**
   - Contains a session GUID to track whether protection is currently active.
4. **Local Diagnostic Logs (`%LOCALAPPDATA%\PrivGuard\Logs\PrivGvard-*.log`):**
   - Structured diagnostic logs recording application startup, operation success/failure, native error codes, and recovery steps.
   - Stored in human-readable rolling text files.
5. **Crash Dumps (`%LOCALAPPDATA%\PrivGuard\CrashReports\crash-*.json`):**
   - Written only when an unhandled exception or critical hardware error occurs. Contains exception stack traces, OS version, and runtime diagnostic metadata.

---

## 4. Purpose of Data Use

All accessed and stored information is used exclusively to:
- Display accurate hardware device names in the user interface.
- Apply and verify requested privacy controls.
- Provide reliable rollback to original device states when protection is turned off or the app is closed.
- Enable crash recovery upon restart.

---

## 5. Remote Data Collection & Network Communications

- **Zero Remote Telemetry:** PrivGvard contains **no** analytics beacons, marketing trackers, telemetry collectors, or crash-reporting webhooks.
- **Zero Cloud Storage:** No user preferences, device IDs, or session journals are ever transmitted to any remote server or third-party service.
- **No Background Network Traffic:** The application does not communicate with external servers during normal operation.

---

## 6. Third Parties & Data Sharing

Because PrivGvard does not transmit data over the network:
- No personal data or device information is shared with, sold to, or accessible by third parties.
- If you voluntarily submit a diagnostic file or screenshot when opening a public GitHub issue, you control the submission. You are advised to review and redact any local file paths or device names before public posting.

---

## 7. Data Protection & Security Controls

- **Access Control:** All local files are written within the current user's profile directory, protected by standard Windows NTFS file system permissions (DACLs restricted to your Windows user account and Administrators).
- **Transient Elevated Worker:** High-privilege hardware operations communicate via an in-memory named pipe protected by 256-bit cryptographic nonces and bilateral kernel PID verification. No credentials or passwords are ever stored.

---

## 8. User Control & Choices

You have full control over PrivGvard at all times:
- You choose which device (Camera, Microphone, or Both) to protect.
- You choose between Standard Protection (no administrator rights needed) and Secure Protection.
- You can enable or disable Windows autostart at any time from the in-app Settings or Windows Task Manager `StartupApps`.
- You can turn off protection at any time, which immediately restores all original device and policy states.

---

## 9. Data Retention & Deletion

- **Retention:** Configuration files and recovery journals are retained locally for as long as PrivGvard remains installed.
- **Automatic Cleanup:** Rolling logs automatically retain only recent execution history.
- **How to Completely Delete All Data:**
  1. Open PrivGvard and ensure protections are disabled (this restores original device states).
  2. Uninstall PrivGvard via Windows Settings > Installed Apps (or PowerShell `Remove-AppxPackage`).
  3. Delete the local directory `%LOCALAPPDATA%\PrivGuard` and the marker `%USERPROFILE%\AppData\Local\PrivGvard\Recovery`. All stored preferences, recovery journals, logs, and crash reports will be permanently removed.
